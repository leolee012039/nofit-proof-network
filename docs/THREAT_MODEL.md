# Threat model

Scope: the demo app as built (Sandbox payments, fictional data). Each threat lists the control and the test that exercises it.

| #   | Threat                                                                                                                                      | Control                                                                                                                                                                                                                                                                                                                                                                  | Evidence                                                                                                                |
| --- | ------------------------------------------------------------------------------------------------------------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------ | ----------------------------------------------------------------------------------------------------------------------- |
| T1  | **Payment replay / double capture** (double-click, retries, concurrent requests)                                                            | CAS lock `CAPTURABLE → CAPTURING`; stable `PayPal-Request-Id` per order; re-read before capture; unique captured payment per contract; run #1 inserted with `ON CONFLICT DO NOTHING`                                                                                                                                                                                     | `paypal-security.test.ts`: replayed + concurrent capture → 1 provider capture, 1 run                                    |
| T2  | **Forged webhook** marks a contract paid                                                                                                    | Postback signature verification before any storage; rejected events are not stored; fixture mode accepts no webhooks; webhook body never trusted for money (order re-read from PayPal)                                                                                                                                                                                   | forged + missing-header webhooks → `WEBHOOK_REJECTED`, 0 rows                                                           |
| T3  | **Duplicate / out-of-order webhooks** double-run proofs                                                                                     | Unique `paypal_event_id`; finalize only from resolvable states; idempotent run insert                                                                                                                                                                                                                                                                                    | duplicate webhook → `DUPLICATE_IGNORED`, 1 run                                                                          |
| T4  | **Wrong amount** (client sends $0.01, tampered provider data)                                                                               | Client amount never read; amount from contract; verification of capture amount (minor units), currency, reference, custom id, payee                                                                                                                                                                                                                                      | client `amount: 0.01` ignored; provider `0.01`/EUR/payee mismatch → `VERIFICATION_FAILED`, `NEEDS_REVIEW`, never `PAID` |
| T5  | **Paying or proving without approval**                                                                                                      | State machine + scope-hash checks; triggers forbid proof states without a captured payment and forbid tenants from setting payment states                                                                                                                                                                                                                                | forged run insert and tenant `PAID` update rejected by Postgres                                                         |
| T6  | **Uncertain capture** (timeout, lost response) treated as success or failure                                                                | `CAPTURE_UNKNOWN` state, idempotent retry, server-side reconcile; UI distinguishes "captured, webhook pending" from "not paid"                                                                                                                                                                                                                                           | lost response → idempotent retry; persistent loss → `CAPTURE_UNKNOWN` → reconcile → `CAPTURED` once                     |
| T7  | **Tenant leakage** (IDOR, cross-tenant reads/writes)                                                                                        | RLS per org on every tenant table; services check party membership; 404 instead of 403 for other tenants' ids                                                                                                                                                                                                                                                            | raw queries in another tenant return 0 rows; forged insert rejected; E2E second buyer → 404                             |
| T8  | **Prompt injection** in documents or buyer notes ("approve payment", "mark FIT", "price $0.01")                                             | Policy decides before the model; documents wrapped as untrusted data; injection screen; untrusted uploads never policy evidence; model status recorded, not used; System Agent cannot approve or price                                                                                                                                                                   | injected upload + notes → same status/price; fake model claiming FIT overruled                                          |
| T9  | **Fake proof / evidence tampering**                                                                                                         | Runner is deterministic; SHA-256 artifact digest recomputed when outcomes are used; completed runs and outcomes immutable; tampered digests excluded                                                                                                                                                                                                                     | tampered outcome excluded; `proof:replay` reproduces stored digests                                                     |
| T10 | **Stale evidence** used for a new decision                                                                                                  | TTL (`expires_at`), version match against the requested API version                                                                                                                                                                                                                                                                                                      | expired / v1 outcomes excluded with reason                                                                              |
| T11 | **Unsafe sharing** of outcome data                                                                                                          | Outcome records readable only by the two parties; reuse limited to the seller under the consent captured at contract acceptance, revocable by the buyer organization in `sharing_consents` (the seller can read but not change it); cross-org network is out of scope                                                                                                    | RLS tests, `outcome-memory.test.ts`                                                                                     |
| T12 | **Secret leakage**                                                                                                                          | Secrets only in server env; never sent to the browser (client ID only); never stored; errors return generic messages; webhook payloads stored as digest + sanitized summary                                                                                                                                                                                              | DB/audit dump contains no secret, token or Basic header                                                                 |
| T13 | **Production misconfiguration**                                                                                                             | Fail closed on non-sandbox `PAYPAL_ENV`/host, partial credentials; `SESSION_SECRET` required off-localhost                                                                                                                                                                                                                                                               | `configuration fails closed` unit tests                                                                                 |
| T14 | **CSRF**                                                                                                                                    | SameSite=Lax httpOnly session cookie; `Origin` must match `Host` on mutations                                                                                                                                                                                                                                                                                            | manual curl check (cross-origin POST → 403)                                                                             |
| T15 | **Read-only reviewer writes**                                                                                                               | `app_can_write()` in RLS write checks + role checks in services                                                                                                                                                                                                                                                                                                          | reviewer insert rejected by RLS                                                                                         |
| T16 | **Two checkouts for one contract** (SDK + redirect, double tab) both approved and captured                                                  | Partial unique index: one live order per contract; an open order is reused for the same flow, otherwise voided before a new one is created; voided orders are never capturable                                                                                                                                                                                           | "two checkouts … can never both be captured"                                                                            |
| T17 | **Paying a cancelled contract**                                                                                                             | Cancel voids payable orders in the same transaction; capture requires `PAYMENT_PENDING`; money moved for an inactive contract is flagged `NEEDS_REVIEW` and never starts a proof                                                                                                                                                                                         | "a cancelled contract cannot be paid"                                                                                   |
| T18 | **Webhook lost after a processing error**                                                                                                   | Dedupe row deleted on failure so PayPal's retry is processed; concurrent deliveries get 409; abandoned rows expire                                                                                                                                                                                                                                                       | "webhook that fails mid-processing is retried"                                                                          |
| T19 | **Early/stale capture events dead-end a payment**                                                                                           | Only a `COMPLETED` provider order can change payment state; anything else is a no-op                                                                                                                                                                                                                                                                                     | "PENDING/DENIED webhook for a not-yet-captured order changes nothing"                                                   |
| T20 | **One party writes the other party's approval**                                                                                             | Trigger: buyers cannot set seller approval fields or seller statuses and vice versa                                                                                                                                                                                                                                                                                      | "each party can only write its own approval fields"                                                                     |
| T21 | **Destructive demo endpoints on a public deployment**                                                                                       | Global demo reset and fixture payments default ON only for localhost; hosted demos must opt in explicitly. A production build without `APP_BASE_URL` counts as hosted (fails closed)                                                                                                                                                                                     | config unit tests; "deployment detection fails closed"                                                                  |
| T22 | **Service-layer bypass** (a bug or raw query in a tenant session forges contracts, skips approval, rewrites terms, assessments or requests) | Triggers (migration 0005): contracts created only by the seller's fit engine with no approvals and matching request/assessment; full contract state machine in SQL (kept equal to the TypeScript table by a test); approvals written once with their own status move; terms frozen in tenant sessions; requests and assessments immutable except state / seller override | `ecc-review.test.ts`: forged insert, acceptance skip, price change, assessment and request rewrite all rejected         |
| T23 | **Fabricated proof evidence** (run created as PASSED, QUEUED→PASSED skip, outcome with a forged digest or result)                           | Runs must be created `QUEUED`, move only `QUEUED→RUNNING→terminal`, and carry evidence only when completed; outcome insert must match a completed run's ids, parties, result and digest                                                                                                                                                                                  | "a proof run cannot skip RUNNING"; "outcome record must match its completed run"                                        |
| T24 | **"Payment failed" shown after PayPal already captured** (local database error after the provider call)                                     | Finalize failure releases to `CAPTURE_UNKNOWN` and answers "Do not pay again: use Check status with PayPal"; reconcile records the capture once                                                                                                                                                                                                                          | "a local failure after PayPal captured is CAPTURE_UNKNOWN …"                                                            |
| T25 | **Webhook lost during a PayPal outage**                                                                                                     | A failed verification _call_ (network, 5xx, our auth) answers 502 so PayPal retries; only a refused envelope or a non-SUCCESS verdict is a 401 rejection                                                                                                                                                                                                                 | "a PayPal outage answers 502 … a refused envelope is 401"                                                               |
| T26 | **Malformed request bodies** (arrays, wrong types, oversized bodies, `{"$ne":…}` objects)                                                   | `readJson` accepts JSON objects only and checks `Content-Length` before reading; typed `stringField` / `booleanField` reject wrong types                                                                                                                                                                                                                                 | `http-and-config.test.ts`                                                                                               |
| T27 | **Lock-order deadlock** between cancel / new checkout and capture finalize                                                                  | Every path locks payment rows before the contract row                                                                                                                                                                                                                                                                                                                    | code review (same order in cancel, create order, finalize)                                                              |
| T28 | **Misconfigured real Postgres** silently disables tenant isolation                                                                          | Startup checks that `app_tenant` exists, is grantable to the connecting user and does not bypass RLS; refuses to start otherwise                                                                                                                                                                                                                                         | `openPostgres` check (not exercised by PGlite tests)                                                                    |

## Residual risks / not covered

- Demo persona sessions are not a real identity system: anyone who can reach a hosted demo can pick any persona, and sessions cannot be revoked server-side. Acceptable for fictional demo data only; replace with Supabase Auth (or similar) before any real use.
- If a hosted demo opts in to `DEMO_RESET`, any visitor can wipe the shared demo data.
- `TRUNCATE` by the table owner (used by demo reset) bypasses the append-only row triggers.
- PGlite single connection: denial of service by slow requests is not mitigated.
- No rate limiting on API routes.
- The webhook verification postback depends on PayPal availability; during an outage events are answered with 502 and rely on PayPal's retries (plus manual reconcile).
- The database guards are defence in depth for tenant sessions and obvious forgeries; the table owner (payment service, migrations) can still write anything, so the owner credentials must stay server-side.
- Live PayPal Sandbox behaviour of the JS SDK v6 path has not yet been verified (see `STATUS.md`).
- Payee verification is enforced when the seller has set a payout account (the payee stored with the order at creation) or `PAYPAL_MERCHANT_ID` is set; otherwise the ledger records the check as skipped.
